## Interface available in the AgenticReplay candidate

- Public commands are `agenticreplay codex-service register [--config <absolute-path>] --json`, `agenticreplay codex-service status --json`, and `agenticreplay codex-service disable --json`. Pass the canonical Git worktree as the child process cwd to register. Repeat registration in another worktree to authorize it. Registration affects the current macOS user and uses the bundled AgenticReplay executable; there is no background setup to run from the chat.
- Status is `running`, `stopped`, `configuration_changed`, `disabled`, or `unsupported`. A registration reports `socketPath`, `baseUrl`, and canonical `worktrees`; consume the socket only if status is `running` and the current canonical root is in the allowlist. Endpoint conflicts are errors from registration. A stopped or incompatible executable is not proof that recording is enabled.
- Invoke the CLI from the actual installed Kiokuko dependency, using an absolute path and `process.execPath`. Do not rely on PATH, a source checkout, or `npx`. Resolve the dependency relative to Kiokuko, validate its package/bin identity, and use a bounded execution time and output size. The public root package exposes `bin/agenticreplay.js` through its npm bin. Include a real installed package test because module export paths and installed bin paths differ.
- The stable private Unix socket is returned by status. Use the existing newline-delimited `{cwd, sessionId, turnId}` to `pending`, `unavailable`, or `sealed` contract. A sealed reply is `{status:"sealed", traceDirectory}`. No changes are needed to the request or review storage schema solely for service discovery.

## Implementation

1. Add explicit opt-in to the normal `kiokuko setup` flow, for example `kiokuko setup --clients codex --codex-dock-record` from the Git worktree to authorize. A setup without this choice must not change API routing or register a worktree. Reject unsupported OS, no Codex client selection, or an invalid Git worktree for the opt-in. Respect dry run and report planned work without creating a service. Run registration after the Codex config, hooks, database, and MCP setup have succeeded so setup does not overwrite the recorder's endpoint. Pass the exact profile config path selected by setup. If registration fails, surface the actual actionable failure and the state of ordinary setup. Preserve user settings and let the recorder own its endpoint and rollback. Explain the one-time quit and Dock relaunch. Document status and disable through the AgenticReplay CLI.
2. In `src/mcp/server.ts` and `src/mcp/codex-desktop-review.ts`, preserve explicit `AGENTICREPLAY_CODEX_REVIEW_SOCKET` as the first choice for `record codex --desktop`. Preserve explicit attached recording via `AGENTICREPLAY_RUN_DIR`. For ordinary Dock startup with neither override, discover the service using the installed AgenticReplay status command asynchronously and verify the current worktree against its reported allowlist. Use the existing hook-derived binding and completed-turn transcript check. Keep all filesystem ownership and socket mode checks in the real socket consumer. Do not turn transport completion into evidence of Codex turn completion.
3. Keep normal checkpoint completion independent from service discovery and native elicitation. Missing CLI, unsupported OS, disabled or stopped service, unsafe socket, malformed reply, and out-of-scope root must not fail the checkpoint or trigger a review. If the socket returns `pending`, use the existing bounded retry with cancellation. `unavailable` ends that review attempt. If the recorder restarts during review, fail closed or retry only within the existing deadline when the error is transient. Do not silently substitute a different turn, worktree, or recording. Keep one review per eligible run and require native elicitation capability.
4. Reuse the existing trace evidence validation in `src/memory/replay-review.ts` and the native review. Review and approval apply to the exact displayed proposal. The user approves it in the real UI. Capture the resulting receipt and use the actual connected Codex MCP session to search for the saved item.
